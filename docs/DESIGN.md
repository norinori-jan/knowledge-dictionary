# 設計メモ

## 位置づけ

```
quick-ref        収集・整理        AIに聞いたこと・メモ
   │  JSON書き出し→取り込み
   ▼
知識辞書          検索・参照        用語・Q&A・自分の理解   ← このリポジトリ
   │  （将来）
   ▼
flow-mind        関係性            知識どうしのつながり
```

- 辞書は、quick-ref の一機能ではなく、**単独で動く**アプリです。
- quick-ref は「最初のクライアント」。いまは、書き出しJSONの取り込みでつなぎます。
- flow-mind は変更しません。連携は、辞書側が育ってから決めます。

## データモデル（IndexedDB `knowledge-dictionary` v1）

### entries（項目＝辞書の1項目）
| 項目 | 内容 |
|---|---|
| id | 一意ID |
| term | 見出し語（大文字小文字・全角半角を区別せず、同じなら同じ項目） |
| oneLine | 一言説明 |
| tags | タグの配列 |
| related | 関連用語の配列 |
| note | 自分の理解（AIの回答とは別） |
| kind | `term`（用語）/ `howto`（手順）/ `idea`（考え方） |
| aliases | 別名（統合した語など）。見出し語と同じく、検索・リンクで引ける |
| cat / lvl / prereq | 分野（`大/小`・最大2階層）／レベル（1基礎・2応用・3発展）／前提にする項目の見出し語 |
| nextAt / rvStreak / rvCount | 次に復習する時期／連続で理解済みにした回数／復習した回数 |
| understanding | `unknown` / `learning` / `known` |
| checkedAt | 理解度を最後に確認した日時 |
| createdAt / updatedAt | 日時（ms） |

### qas（Q&A＝原資料）
| 項目 | 内容 |
|---|---|
| id | 一意ID（quick-ref から取り込んだものは `qr_<元のid>`） |
| entryId | 属する項目 |
| question / answer | AIに聞いたこと／回答 |
| judgment | 自分の判断 |
| viaApp / model | アプリの「AIに聞く」で作ったか／使ったモデル |
| sourceType / sourceUrl | ChatGPT・Claude など／元の会話のURL |
| createdAt / updatedAt | 日時（ms） |

考え方：**Q&A ＝ 原資料、項目 ＝ 整理された知識**。同じことを10回聞いても、1つの項目にまとまります。

### 書き出し形式
```json
{ "app": "knowledge-dictionary", "version": 1, "exportedAt": 0, "entries": [], "qas": [] }
```
読み込みは、`id` ごとに `updatedAt` が新しいほうを採用します。

## 検索のしくみ

1. 検索語を、空白で語に分ける。全語を含む項目だけを残す（AND）。
2. 語ごとに、当たった場所で点をつけて足す。

| 当たった場所 | 点 |
|---|---|
| 見出し語が完全一致 | 100 |
| タグが完全一致 | 80 |
| 見出し語に含む | 50 |
| タグに含む | 30 |
| 一言説明 | 20 |
| 関連用語 | 15 |
| 自分の理解 | 8 |
| Q&A（質問・回答・判断） | 5 |
| 2文字ずつの曖昧一致（3文字以上の語のみ、2/3以上） | 0.5 |

3. 点の高い順、同点は更新が新しい順。
4. 比較は、全角半角・大文字小文字をそろえてから行う（NFKC＋小文字）。

意味検索（embedding）は入れていません。「82%一致」のような数字も出しません。文字の一致では、意味の近さを正直に表せないためです。

## 保存前検索（似た項目）

質問と見出し語から、次の順で似ている項目を最大3件出します（しきい値 0.4）。
1. 項目の見出し語が、書いた文の中に入っている → 1.0
2. タグ・関連用語が入っている → 0.6
3. 2文字ずつの重なり率

## AI整理

- 送り先：quick-ref と同じ Worker の `POST {endpoint}/ai`（`Authorization: Bearer <同期トークン>`）。
  本体は `{ provider, model, maxTokens, prompt }`、返事は `{ text }`。キーは Worker だけが持ちます。
- 送る内容：質問と回答だけ。**自分の判断は送りません。**
- 送る前に、秘密らしい行（`sk-…`、`AIza…`、`Bearer …`、`password=…`、40文字以上の英数字の列、秘密鍵、GitHubトークン）を**行ごと除きます**。除いた行数は確認画面に出します。
- AIには JSON だけを返させ、`term / oneLine / tags / related` の**候補**として表示します。確定は人が押したときだけ。
- 既存の見出し語・既存タグを渡し、合うものがあれば使わせます（項目が増えすぎないように）。
- 設定が空のときは、同じブラウザの quick-ref の設定（`qr_sync_endpoint` / `qr_sync_token`）を借ります。

## リンク（v0.2）

- 本文の `[[見出し語]]`／`[[見出し語|表示名]]` を、保存せずその場で解析（`rebuildLinks`）。見出し語は正規化して照合。
- outLinks（項目→リンク先）と inLinks（項目→被リンク元）をメモリに持つ。DBには本文だけを保存。
- つながり図は、力学配置のSVG（外部ライブラリなし）。

## AIに聞く（v0.2）

- 送り先は AI整理と同じ `POST {endpoint}/ai`。maxTokens 1200。秘密行は除去。
- 共通指示（`kd_sys`）を先頭に付ける。参考に選んだ項目の「自分の理解」を「【参考：以前の自分の整理】」として添付。
- **費用は API トークン課金で、月額プランとは別枠**。1日の上限（`kd_limit`、初期30）と回数（`kd_usage`）を端末内で数え、上限超えは確認を出す。

## 同期（v0.3）

- `GET/PUT {endpoint}/sync/knowledge-dictionary`（quick-ref と同じ形式 `{data:{…}}`、`Authorization: Bearer`）。
- 同期＝先に受信して統合→必要なら送信（空の端末が上書きしない）。`id` ごとに `updatedAt` が新しいほうが勝つ。
- 削除は墓標（`kd_tomb`、90日で破棄）で伝える。同じ見出し語は統合し、Q&Aを付け替える。
- 自動：初回の手動同期のあと、保存の2.5秒後・起動時・画面に戻ったとき。
- 暗号化はなし（クラウドには平文で預けます）。

## 辞書AI（v0.5）

- **辞書に聞く：** `retrieve()` が、質問と各項目を2文字ずつの重なり（ひらがなだけの組は除く）・見出し語／タグの直接言及で採点し、上位6件＋リンク先を選ぶ。材料（一言・自分の理解・Q&A2件・自分の判断）を7500字までにしてAIに渡し、「材料にあることだけで答える・根拠は[[見出し語]]で示す」と指示する。関連項目が無ければ送らない。意味検索（embedding）はまだ使っていない。
- **復習：** 質問生成と採点の2回（JSONで返させる）。採点は材料を正解の基準にする。
- **つながり提案：** 対象の項目＋ほかの項目の一覧（最大120）を渡し、既存の見出し語だけを links に許す（一覧にない語は捨てる）。
- **自動整理：** AI整理と同じプロンプト（kind を追加）。空欄だけ埋め、見出し語は変えない。
- すべて `callAI()` を通るので、1日の上限・使用量・秘密行の除去が効く。

## 統合・言い換え・取り込み（v0.6）

- **統合：** 吸収される側のQ&Aを `entryId` 付け替え、見出し語を `aliases` に。理解度は低いほうを採る（安全側）。吸収される側の id は墓標で同期に伝える。
- **似た項目の検出：** 見出し語の包含・見出し語の2文字重なり（0.6以上）・タグ2つ以上共通かつ一言が似ている、のいずれか。
- **言い換え：** `retrieve()` の結果が3件未満のときだけ、辞書の語彙（見出し語250・タグ80）をAIに渡し、関係しそうな語と言い換えを返させて再検索する（`expandQuery`）。語彙にない語は無視する。
- **検索の高速化：** 項目ごとの2文字集合をキャッシュ（`rbCache`、変更時に破棄）。600項目・Q&A1800件で、2回目以降は約0.02秒。
- **quick-ref のクラウド取り込み：** `GET {endpoint}/sync/quick-ref`（読み取りのみ）→ `type==='ai_qa'` かつ非保護のものだけを、JSON取り込みと同じ処理（`qr_<id>` で重複防止）で入れる。

## 体系・学習（v0.7）

- **体系化：** 分野のない項目を40件ずつAIに渡し、`{term, cat, lvl, prereq}` を返させる。既存の分野を渡して再利用させ、語彙にない前提・存在しない項目は捨てる。候補として見せ、採用で書き込む。
- **復習の順序：** 復習の時期が来ている項目（`nextAt` ≤ 今、`nextAt` が無ければ未理解・理解中）を、(1) 前提がすべて理解済み、(2) レベルが低い、(3) 未理解が先、(4) 最後に確認した日が古い、の順に並べる。
- **間隔：** 理解済み＝3→7→14→30日（連続回数で延びる）、理解中＝1日、未理解＝すぐ。いずれも固定の簡易ルールで、忘却曲線を測るものではない。
- **サイクル画面：** 各段階の件数（取り込みは除く）から「次はこれ」を決める：整える → 体系にする → 復習する の順で、最初に件数が1以上のもの。
- 学習ログは `localStorage`（`kd_study`、日付ごとの問数）。端末間では同期しない。

## 書庫（v0.8）

- **AIは使わない。** 項目のタグから、`tagIndex()`（正規化したタグ → 項目の集合）を作るだけ。
- **区画：** 2項目以上に付いたタグの組で、共通項目が2以上かつ「小さいほうの8割以上が共通」かつ「大きいほうの3割以上が共通」なら同じ区画（単連結）。区画名は最も大きい棚の名前。1項目だけのタグは「ひとつだけの棚」。
- **整理のおすすめ：** (1) 項目の集合が同一、(2) 名前が包含関係で長さの差が3字以内（または共通項目が半分以上）、(3) 2文字の重なりが0.7以上、のいずれか。小さいほうを大きいほうへ統合する提案。
- **タグ操作：** `retag(from, to)` が、該当の全項目のタグを置換（`to` が空なら外す）し、`updatedAt` を更新するので同期される。
- 棚の中身は開いたときに描画（遅延）。800項目・50棚でも描画は約0.02秒。

## 保存と注意（iOS）

- Safari のタブと、ホーム画面のアプリは、保存領域が別です。
- `navigator.storage.persist()` を、最初の保存のあとに求めます（認められると、端末による自動削除がされにくくなります）。
- それでも消える可能性はゼロではありません。そのため、書き出しの知らせ（3件以上・7日）を入れています。
- IndexedDB が使えない環境では、メモリだけで動き、画面に警告を出します。

## Service Worker

同じ場所のファイルは「ネット優先、だめなら保存済み」。AIなど、ほかの場所への通信には触りません。更新したら `sw.js` の `CACHE` 名を変えると、古い保存が消えます。

## 既知の制限

- 同期は最終更新が新しい側が勝つ方式（同じ項目を同時に別々に編集すると、片方の編集が負ける）
- 使用量の数え方は端末内の概算（課金の正確な値は各社の画面で確認）
- 暗号化なし
- 項目どうしの統合ボタンなし（見出し語を直すと、同じ見出し語のものにまとまる）
- 取り込んだ quick-ref のメモは、題名がそのまま見出し語になる（AI整理で付けた題名なら、ほぼ1件1項目）
- 関連する項目は、同じタグだけから出す
